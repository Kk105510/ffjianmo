# FF14 建模招募检索

面向《最终幻想 XIV》国服的独立队员招募检索网页。手机、电脑自适应，黑白简洁风格，保留大区辨识色。

## 功能

- 全部招募统一展示，不区分卖家、买家，避免误判文案
- 16 种种族 / 性别快捷筛选；在关键词框直接输入「猫男」也会使用相同的建模匹配。兼容常见简称以及 `猫兔人男` → 猫男、兔男、人男等合并写法（无性别时不擅自推断）
- 匹配 `50/30`、`100-60` 等形式；原文中的数字组合以浅粉色突出，并保留原始分隔符。不擅自定义货币单位
- 关键词、大区、`/10`～`/60`、发布时间排序，客户端组合筛选
- 多页招募去重、上限控制、部分页面错误提示；复制招募内容
- 暗色模式、可自定义代理根地址

## 发布

建议新建一个**独立的** GitHub 公开仓库（例如 `ff14-model-finder`）。将 `index.html`、`styles.css`、`app.js`、`favicon.svg` 上传到仓库根目录。打开 Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main / (root) → Save。

如只是本地打开 `index.html`，某些浏览器 / 文件预览器可能禁止执行脚本或发起跨域网络请求。优先通过 GitHub Pages URL 检查。

## 招募数据来源与限制

站点默认请求 `https://xivpf.littlenightmare.top/api/listings`（依据一个公开国服招募查询项目使用的 XIVPF 接口格式）。该服务不是 FF14 游戏官方接口，数据依赖在线玩家采集，可能存在延迟、缺页或停服，且其跨域政策、接口可用性并未在此环境内完成真实联网测试。

GitHub Pages 本身**没有服务器端转发能力**。若出现 CORS 或 API 不可用，可按下面步骤自行部署代理，但代理也不能修复上游真正宕机的问题：

1. 在 Cloudflare Dashboard → Workers & Pages 创建一个 Worker。
2. 将 `cloudflare-worker.js` 内容粘贴至 Worker 代码并部署。
3. 取得自己的 `https://xxx.workers.dev` 地址，在网站底部「数据源设置」中填写该地址，保存后重新读取。
4. 如上游 API 发生变化，修改 Worker 的 `UPSTREAM` 和前端 JSON 格式即可；不要使用不可信的公共万能 CORS 代理。

本项目不会搜集账号密码，也不能在网页中直接加入游戏内队伍。查询列表中的发起人、服务器、剩余时间、内容以来源返回为准；不要误认为匹配结果完全准确。

## 技术说明

静态 HTML / CSS / JavaScript，无依赖、无构建步骤。JSON 字段适配 `data[] / listings[] + pagination.total_pages` 格式。最多读取 80 页，每页 100 条，并发 4 页，部分页失败则显示不完整提示。每次由用户点击按钮才主动刷新，避免持续请求上游。

`PRICE_PATTERN` 为启发式数字/时长格式识别，可能出现误报；此工具不区分求租、出租。建模组合识别也无法保证囊括所有玩家的自定义简称。
